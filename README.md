# Селена — прототип Telegram Mini App

Первая интерактивная версия: пять экранов, знакомство, утреннее послание, карта дня, выбор трёх карт, нумерология, локальный дневник, настройки уведомлений. Рабочее название можно изменить.

## Границы этой версии

- Это самостоятельный веб-прототип, не зарегистрированный Telegram-бот.
- Нет серверного аккаунта, Telegram-авторизации, ИИ, платежей и отправки уведомлений.
- Данные хранятся только в localStorage этого браузера. Лимит истории — 150 записей. Не использовать для чувствительных данных.
- Колода: девять символов с общей иллюстрацией и редакционными текстами. Вопрос сохраняется, но его смысл не анализируется.
- Утреннее послание выбирается из готовых текстов по местной дате, знаку, интересам и дате рождения. Это не астрономический расчёт транзитов.
- Карта дня закреплена на местную дату и локальный идентификатор. Знак можно выбрать вручную для пограничных дат.
- Нумерология: сумма всех цифр даты с сокращением до 1–9, включая 11/22/33. Это символическая практика без научной предсказательной силы.

## Показать партнёру

Это веб-прототип для браузера, не бот в Telegram. Партнёру достаточно этой папки.

Не открывать `index.html` двойным кликом: модули и картинки так не подхватятся. Нужен любой статический сервер из папки с файлами:

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

Открыть http://127.0.0.1:4173

Что потыкать: Сегодня → карта дня, Расклады → вопрос и три карты, Портрет → дата рождения, Профиль → имя и темы, Дневник после первой карты.

Репозиторий: https://github.com/alcuvion-boop/selena-prototype

Публичная ссылка: https://selena-prototype.netlify.app

Данные остаются только в браузере того, кто открыл. Это не Mini App внутри Telegram.

## Проверка локально

`python3 -m http.server 4173 --bind 127.0.0.1`

Открыть http://127.0.0.1:4173. Тесты: `node --test domain.test.mjs`.

## Следующий этап

1. Утвердить визуальный стиль и редакционные примеры, подготовить полную оригинальную колоду.
2. Создать бота в BotFather. Не передавать токен через переписку или клиентский код: хранить его на сервере.
3. Подключить публичный HTTPS-адрес мини-аппа.
4. На сервере проверять подпись и свежесть Telegram initData, создать общие профили и историю в PostgreSQL.
5. Подключить ИИ через сервер: строгая схема ответа, заданные карты, ограничения опасных прогнозов.
6. Подключить добровольную рассылку с таймзоной и антидублем.
7. Добавить условия, политику хранения/удаления; модель оплаты — после теста продукта.
